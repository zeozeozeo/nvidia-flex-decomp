# 002 `cs_5_0` — CalculateMortonCodes

## Interface
- `cbuffer constBVH { int gNumItems; }` (b0, 16 bytes)
- `StructuredBuffer<float4> itemLowers` (t0), `itemUppers` (t1)
- `StructuredBuffer<float3> gridLower` (t2), `gridInvEdges` (t3)
- `RWBuffer<uint> indices` (u0), `keys` (u1) — `dcl_uav_typed_buffer (uint,...)`
- thread group 256x1x1

## Algorithm
Per item: `centre = (lower + upper) * 0.5`, `cell = (centre - gridLower) * gridInvEdges * 512`,
truncated (`round_z`) and clamped to `[0, 511]`, then interleaved into a 27-bit Morton key
and written to `keys`; `indices` receives the item index (the radix-sort payload). Out of
range threads write `0xffffffff` to both.

## Interface detail
The Morton interleave is the `Part1by2` mask chain of `Morton3<1024>` (`bvh.part1.cu`), but
with the D3D build's own masks, transcribed literally from the bytecode:
`0x010000FF`, `(v & 0xFF) << 8` via `bfi`, `0x0100F00F`, `0x010C30C3`, then an un-masked
`v ^ (v << 2)` and the packing masks `0x04924924 / 0x02492492 / 0x01249249`. Note this is
9-bit packing (27-bit key), not the CUDA 10-bit form.

## Inference
- The `bfi(8,8,src,0)` in the bytecode is `(src & 0xFF) << 8`; HLSL has no `bfi`, so the
  expression is written out. Masks are byte-identical to the bytecode.
- The bytecode's `r0.xyz` holds `(z, y, x)` after the `.zyx` swizzles on the three input
  vectors; the transcription feeds the spread with `(cz, cy, cx)` to keep the key layout.
