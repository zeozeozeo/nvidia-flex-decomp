# 035 `cs_5_0` — CalculateInflatableVolume

**Status: reconstructed** — `recon/src/dx/shaders/035_cs_5_0__CalculateInflatableVolume.hlsl`, gate `1/1`.

## Interface
- no constant buffer
- `StructuredBuffer<Inflatable>` (t0, stride 16: `{int offset, int count, float targetVolume, float stiffness}`),
  `StructuredBuffer<float4> positions` (t1, stride 16), `StructuredBuffer<int> reverseLookup` (t2, stride 4),
  `indices` (t3, stride 4)
- `RWStructuredBuffer<float> lambdas` (u0, stride 4)
- `groupshared`: 16 B record + 4 B scalar + 12 B float3 + 12x512 + 4x512
- thread group 512x1x1; one thread group per inflatable (`SV_GroupID`)

## Algorithm
Thread 0 publishes the inflatable record and zeroes the two accumulators. Pass 1 walks the
inflatable's triangles in 512-element slices, each thread computing
`(p0 + p1 + p2) / (3 * count)`, block-reducing the slice (power-of-two walk over the live count)
and adding the result to a shared float3. Pass 2 repeats the sweep, computing the signed corner
volume `dot(p0 - centre, cross(p1 - p0, p2 - p0))`, reducing it the same way and adding it to a
shared scalar. Thread 0 finally writes
`lambdas[group] = t^3 * stiffness * (sum - targetVolume)` with `t = |targetVolume| / max(|0.01 * targetVolume|, |sum|)`.

  this shader only produces the lambda, so the recovered source name is taken as
  `CalculateInflatableVolume`. The gate does not compare entry names.
- The `0.01` and `^3` factors are read straight from the bytecode (`9.99999978e-03`,

- Same volume/lambda math as 033 and 036 (cross-checked against both).
