# 037 `cs_5_0` — SolveContacts

**Status: reconstructed** — `recon/src/dx/shaders/037_cs_5_0__SolveContacts.hlsl`, gate `1/1`.

## Interface
- `cbuffer consts` (b0, 32 registers)
- `StructuredBuffer<int> collisionCounts` (t0, stride 4), `StructuredBuffer<float4> collisionPlanes`
  (t1, stride 16), `prevPositions` (t2, stride 16), `collisionVelocities` (t3, stride 16)
- `RWStructuredBuffer<float4> positions` (u0, stride 16, read-modify-write)
- thread group 256x1x1

## Algorithm
One thread per particle with a non-zero contact count. Each contact plane is resolved against
the **running accumulated position** (`d = dot(accum, plane.xyz) + plane.w`), with adhesion
added to the accumulation, static friction inside `vt^2 < (dist * kStaticFriction)^2`, and
dynamic friction clamped by `min(rsqrt(vt^2) * (-dist * kDynamicFriction), 1)`. The accumulated
xyz replace the particle position; `w` is preserved.

## Inference
- Same buffer set as 026 (`SolveContacts`), but 026 evaluates `d` against the entry position
  while this shader tracks the accumulated one; the two are therefore the two instantiations
  of the same kernel, and the recovered entry name is shared.
- The `w` lane is re-stored unchanged (`store_structured u0.xyz` writes three components only);
  the HLSL stores `float4(accum, pos.w)`.
- Constant roles follow 026/074: `cb0[16].w` = `kDynamicFriction`, `cb0[17].x` =
  `kStaticFriction`, `cb0[17].z` = `kAdhesion`, `cb0[18].z` = `kCollisionDistance`,
  `cb0[31].w` = `kMaxContactsPerParticle`.
