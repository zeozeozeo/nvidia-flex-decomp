# 022 `cs_5_0` — UpdateVertexNormals

**Status: reconstructed** — `recon/src/dx/shaders/022_cs_5_0__UpdateVertexNormals.hlsl`, gate `1/1`.

## Interface
- `cbuffer consts` (b0, 27 registers; only `cb0[26].w` = `kNumTriangles` is read)
- `StructuredBuffer<int> indices` (t1, stride 4), `StructuredBuffer<float3> triNormals` (t2, stride 12)
- `RWByteAddressBuffer accum` (u0, `dcl_uav_raw`) — RDEF name `InterlockedFloat::accum`
- thread group 256x1x1

## Algorithm
One thread per triangle. For each of the three corner indices it performs nine float atomic
adds (three per corner) of the triangle normal's components at byte addresses
`index * 16 + {0, 4, 8}`, i.e. the accumulator is a `float4` per vertex of which xyz is the
running normal sum.

## Inference
- The atomic add is the shipped compare-exchange loop (`imm_atomic_cmp_exch` x9); it is
  written as `InterlockedCompareExchange(accum[addr], expected, asuint(asfloat(expected) + value), old)`
  which vkd3d compiles to the identical instruction. The member-function form is rejected by
  the front end; the free intrinsic over an indexed raw lvalue is accepted.
- The accumulator's `w` lane is never touched here, so the vertex writer that consumes it must
  be a later pass (not yet reconstructed).
