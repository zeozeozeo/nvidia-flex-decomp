# 081 `cs_5_0` — RadixSortScan

## Interface
- `cbuffer params` (b0, 2 registers)
- `Buffer<uint4> countersSrc` (t0), `RWBuffer<uint4> countersDst` (u0)
- `groupshared uint sScan[256]`, thread group 256x1x1

## Algorithm
`numItems = numCounters >> 2`; process 256 `uint4` items per block, reduce each item's four
components to a lane value, inclusive-scan the lane values, and write the running prefix back as
four offsets; the block total is carried into the next block.

## Inference (recorded, not exact)
- The shipped shader has two code paths (group 0 runs the serial loop, other groups the parallel
  one) and a hand-unrolled 12-step scan pattern with a 4-way stride. The reconstruction keeps the
  parallel path only and uses a Hillis-Steele scan; the four-component offset layout written to
  u0 is reconstructed from the `store_uav_typed u0.xyzw` operand order.
- Entry-point name is not present in the RDEF; `RadixSortScan` is descriptive.
