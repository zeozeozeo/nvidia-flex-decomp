# 001 `cs_5_0` — BuildHierarchy

**Status: blocked (not reconstructed).**

## Interface
The RDEF/SHEX declare `dcl_uav_structured_opc u7, 256` — the NVAPI shader-extension
opcode buffer (`g_NvidiaExt`, 256-byte elements with `opcode/rid/sid/dst1u/padding0`
members, visible in the RDEF type record).

## Algorithm evidence
`001_cs_5_0.asm` uses `imm_atomic_alloc ... u7` plus `store_structured u7, ..., l(76)`
to append entries through the NVAPI extension.

## Blocker
The `opc` (`D3D11_SB_UAV_HAS_COUNTER` / NVAPI extension) flag on a structured UAV cannot be
expressed in SM5 HLSL: neither the HLSL source language nor the vkd3d-shader front end
provides append/consume or counter UAVs (`AppendStructuredBuffer` is rejected with
`E5030: Unknown modifier`). Any HLSL reconstruction would emit
`dcl_uav_structured u7, 256` without `_opc` and change the host's binding contract,
so this shader is left unreconstructed rather than guessed.
