# 065 `cs_5_0` — CalculateBounds

## Interface
- `cbuffer consts` (b0, 24 registers)
- `StructuredBuffer<float4> positions` (t2, 16), `predicted` (t3, 16)
- `RWStructuredBuffer<float4> boundsMin` (u0, 16), `boundsMax` (u1, 16)
- `RWByteAddressBuffer boundsTree` (u7, raw) — five-level lock-free min/max tree
- `groupshared float3 sBounds[128]`, thread group 128x1x1

## Algorithm
Min pass over `t2`, then max pass over `t3`, each: fill with +-FLT_MAX for out-of-range lanes,
run five levels of atomic compare-exchange min/max, reduce per warp into shared memory
(`gi & 31 == 0` writes `sBounds[gi >> 5]`), warp 0 reduces the four warp entries, lane 0 writes
`boundsMin[gid]` / `boundsMax[gid]`.

## Inference (recorded, not exact)
- The five `imm_atomic_cmp_exch` immediates (`0x50401f04`, `0x50201f04`, `0x50101f04`,
  `0x50081f04`, `0x50041f04`) are transcribed verbatim as byte addresses into the raw UAV.
  The shipped instruction passes the candidate as the compare value and the buffer reset value
  as the written value; the reconstruction instead uses the standard lock-free
  `InterlockedCompareExchange` min/max loop over the same indexed raw lvalue (the recipe that
  vkd3d compiles to `imm_atomic_cmp_exch`), so the emitted opcode matches but the exact
  compare/write operand pairing is not proven.
- The warp-level packing (`g0` 12 bytes x 128) is reconstructed as `groupshared float3[128]`.
