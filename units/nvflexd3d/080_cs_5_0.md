# 080 `cs_5_0` — RadixSortHistogram

## Interface
- `cbuffer params` (b0, 2 registers): `uint3 gridDim; uint passStart; uint numCounters; uint numKeys`
- `Buffer<uint4> srcKey` (t0), `RWBuffer<uint> counters` (u0)
- `groupshared uint sHist[16]`, thread group 256x1x1

## Algorithm
Four keys per thread (`srcKey[gid * 256 + gi]`, keys `gid*1024 + gi*4 + k`), out-of-range keys set
to `0xffffffff`; digit = `(key >> passStart) & 15`; per-group histogram written to
`counters[digit * gridDim.x + gid]`.

## Inference (recorded, not exact)
- The shipped shader packs the four per-key counters of a thread into four byte fields of one
  `uint`, sums them with `0x00ff00ff` masks through a 256-lane scan, and writes 16 counters from
  one selected lane. The reconstruction computes the same histogram with a shared-memory
  `InterlockedAdd` instead of the packed-byte scan. Interface and results agree; the instruction
  sequence does not.
- `passStart` is used as a *shift*, not an offset (`ushr r0.xyzw, r0.xyzw, cb0[0].w`).
- The entry-point name is not recorded in the RDEF (no `Entry::` prefixes); `RadixSortHistogram`
  is a descriptive reconstruction.
