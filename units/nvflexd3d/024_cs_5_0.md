# 024 `cs_5_0` — CalculateBounds

**Status: reconstructed** — `recon/src/dx/shaders/024_cs_5_0__CalculateBounds.hlsl`, gate `1/1`.

## Interface
- `cbuffer consts` (b0, 24 registers)
- `StructuredBuffer<float4> readBoundsLower` (t2, stride 16), `readBoundsUpper` (t3, stride 16)
- `RWStructuredBuffer<float3> bounds` (u2, stride 12, two entries)
- `RWByteAddressBuffer amdIntrinsics` (u7, `dcl_uav_raw`; RDEF name `AmdDxExtShaderIntrinsicsUAV`)
- `groupshared float3` 128 entries; thread group 128x1x1

## Algorithm
Same shape as 039 (lower/upper bounds with `± kRadius`) but the reduction is the AMD
cross-lane variant: lane = `gid & 31`, slice = `gid >> 5`; five rounds of AMD atomic-memory
reads fold the 32-lane slice, lane 0 writes the slice result to shared memory, thread 0 folds
the four slices, and thread 0 writes `bounds[0] = lower - kRadius`, `bounds[1] = upper + kRadius`.

## Inference
- The five u7 addresses (`0x50401f04, 0x50201f04, 0x50101f04, 0x50081f04, 0x50041f04`) are
  constant-folded AMD atomic-memory addresses, not data offsets into a bound buffer.
- Every u7 access is `imm_atomic_cmp_exch dst, u7, addr, value, l(0)`: the compare operand is
  the value and the stored value is zero, so a match stores zero over zero — the instruction
  can never change memory. The HLSL reproduces it verbatim
  (`InterlockedCompareExchange(amdIntrinsics[addr], asuint(value), 0u, old)`).
  The runtime meaning of the returned word depends on the AMD driver extension and cannot be
  validated on this host.
- The element predicate repeats 039's `((n + 127) / 128 + 127) / 128` (see 039's note).
