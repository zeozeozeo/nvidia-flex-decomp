# 025 `cs_5_0` — UpdateTriangles

**Status: reconstructed** — `recon/src/dx/shaders/025_cs_5_0__UpdateTriangles.hlsl`, gate `1/1`.

## Interface
- `cbuffer consts` (b0, 31 registers)
- `StructuredBuffer<float4> sortedNewPositions` (t0, stride 16), `sortedVelocities` (t1, stride 16)
- `StructuredBuffer<int> reverseLookup` (t2, stride 4), `indices` (t3, stride 4)
- `RWByteAddressBuffer accum` (u0, `dcl_uav_raw`; RDEF `InterlockedFloat::accum`)
- `RWStructuredBuffer<float3> triNormals` (u1, stride 12)
- thread group 256x1x1

## Algorithm
One thread per triangle. The face normal `normalize(cross(p2 - p0, p1 - p0))` (zero when
degenerate) is written to `triNormals[tid]`. Then, when `kDrag != 0 || kLift != 0`, the
aerodynamic force is scattered onto the three corners: each corner accumulates
`float4(force * pos.w, 1)` at `index * 16 + {0,4,8,12}` with float atomics (twelve inlined
compare-exchange loops). `force = (dn * kDrag * kDt) * rel + (|rel| * clamp(cos * dn * kLift * kDt, -1, 1)) * normalize(cross(cross(rel, n), rel))`
where `rel = kWind - (v0+v1+v2)/3` and `dn = dot(normalize(rel), faceNormal)`.

## Inference
- The lift vector was identified algebraically from the register stream: the shipped triple of
  `mad`/`mul` reconstructs `cross(cross(rel, n), rel)` exactly (verified numerically against
  the instruction semantics). The face-normal cross order is `cross(p2 - p0, p1 - p0)`,
  i.e. reversed relative to 036's `cross(p1 - p0, p2 - p0)`.
- `pos.w` is the corner weight (inverse mass); the shipped code reuses the `w` lane of the
  position load, which is why the weight is not re-read from another buffer.
- The fourth accumulator channel receives `1.0` per corner, i.e. it counts contributions.
