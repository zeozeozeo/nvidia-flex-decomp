# 006 `cs_5_0` — ComputeTotalBounds (AMD extension path)

## Interface
- `cbuffer constBVH { int gNumItems; }` (b0)
- `StructuredBuffer<float4> itemLowers` (t0/t2), `itemUppers` (t1/t3)
- `RWStructuredBuffer<float4> writeBoundsLower` (u0), `writeBoundsUpper` (u1)
- `RWByteAddressBuffer AmdDxExtShaderIntrinsicsUAV` (u7, `dcl_uav_raw`)
- `groupshared float3[256]`, thread group 256x1x1

## Algorithm
Block-wide min/max over the item bounds. Each component is first pushed through one
`imm_atomic_cmp_exch` against the extension UAV at a fixed opcode address (five groups of
addresses: `1346379524`, `1344282372`, `1343233796`, `1342709508`, `1342447364`, one CAS
per component per group), then combined with `min`/`max`. Lane 0 of each 32-lane group
stores its partial into `groupshared`, thread 0 folds the eight partials, and thread 0 of the
block publishes `float4(min, 0)` / `float4(max, 0)` at `SV_GroupID`.

## Reconstruction note
The five CAS groups are the AMD shader-intrinsics encoding of vector float min/max (the
"UAV" is the extension handshake buffer, the addresses are driver opcodes). They are
transcribed verbatim: `InterlockedCompareExchange(uav[addr], asuint(v.x), 0u, old)` emits
exactly `imm_atomic_cmp_exch r, u7, addr, cmp, 0`, and the reconstruction reproduces all
30 CAS instructions of the shipped shader with identical addresses and operands.
This is the lowered form the driver interprets, not a retry loop, so it is written as a
single CAS per component exactly like the original.
