# 039 `cs_5_0` — CalculateTotalBounds

**Status: reconstructed** — `recon/src/dx/shaders/039_cs_5_0__CalculateTotalBounds.hlsl`, gate `1/1`.

## Interface
- `cbuffer consts` (b0, 24 registers)
- `StructuredBuffer<float4> readBoundsLower` (t2, stride 16), `readBoundsUpper` (t3, stride 16)
- `RWStructuredBuffer<float3> bounds` (u2, stride 12, two entries: [0] lower, [1] upper)
- `groupshared float3` 128 entries (12 B stride in the original `dcl_tgsm_structured`)
- thread group 128x1x1

## Algorithm
Each thread selects its element (`tid < numItems`, otherwise `+FLT_MAX`), stores it in shared
memory, then walks a power-of-two min reduction (64, 32, ..., 1). Thread 0 folds the four
slices, every thread re-reads `g0[0]`, and the same reduction is repeated with `max` seeded by
`-FLT_MAX`. Thread 0 finally writes `bounds[0] = lower - kRadius` and
`bounds[1] = upper + kRadius`.

## Inference
- `cb0[8].y` is `kRadius` (same field use as shaders 021/024/065).
- The element predicate is `((kNumParticles + 127) / 128 + 127) / 128` — two successive
  round-up divisions by the group size, transcribed literally from the bytecode. Why the
  source divides twice (rather than once, as a block-index count would) is **unknown**; no
  other recovered shader uses that form. It does not affect the interface.
- Only one thread group is expected at dispatch, since no block index is used.
