# 032 `cs_5_0` — SolveSprings

**Status: reconstructed** — `recon/src/dx/shaders/032_cs_5_0__SolveSprings.hlsl`, gate `1/1`.

## Interface
- `cbuffer consts` (b0, 26 registers; `cb0[25].y` = `kMaxParticles`)
- `StructuredBuffer<int> halfSpringOpposites` (t1), `halfSpringLengths` (t2, float),
  `halfSpringStiffness` (t3, float), `particleSpringBegin` (t4), `particleSpringEnd` (t5),
  `reverseLookup` (t6), `StructuredBuffer<float4> sortedNewPositionsTex` (t7, stride 16)
- `RWByteAddressBuffer deltas` (u0, `dcl_uav_raw`), `groupshared float3[512]`
- thread group 512x1x1

## Algorithm
Eight threads cooperate on one particle (`particle = tid >> 3`, `lane = tid & 7`). Each lane
walks every 8th half spring of the particle's range, accumulating
`d/|d| * (1/(w0+w1)) * stiffness * (restLength - |d|)` with the sign correction
(`if (stiffness < 0) { diff = min(diff, 0); stiffness = -stiffness; }`) and the two guards
`|d|^2 > 0` / `w0 + w1 > 0`. Lane 0 folds the eight lane results, scales by the particle's
`w`, and adds `float4(sum * pos.w, springCount)` into the particle's 16-byte slot.

## Deviation (front end), documented in the shader header
The final accumulation in the shipped bytecode is
`ld_raw_indexable r3.xyzw, r0.x, u0.xyzw` / `store_raw u0.xyzw`. vkd3d-shader's SM5 front end
has no `Load` on `RWByteAddressBuffer` (only `Store`/`Store2..4`), so the read is spelled as
four non-committing 32-bit atomics (`InterlockedAdd(deltas[addr], 0u, old)`), which return the
stored word and never write. The slot is written by exactly one lane per particle group, so the
value read is identical to a load; only the instruction differs. The write uses
`deltas.Store4` (`store_raw`).
