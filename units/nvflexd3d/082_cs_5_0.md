# 082 `cs_5_0` — RadixSortSort

## Interface
- `cbuffer params` (b0, 2 registers)
- `Buffer<uint4> srcKey` (t0), `Buffer<uint4> srcVal` (t1)
- `RWBuffer<uint4> dstKey` (u0), `RWBuffer<uint4> dstVal` (u1)
- `groupshared` 4 x 1024 bytes-equivalents (`sKey[1024]`, `sVal[1024]`) + two 256-entry scans,
  thread group 256x1x1

## Algorithm
1024 keys per group (4 per thread), out-of-range keys set to `0xffffffff`; 32 passes, one bit each
(least significant first), each a stable partition through shared memory: count zero bits per
thread, exclusive-scan, scatter, reload.

## Inference (recorded, not exact)
- The shipped shader hand-unrolls the per-thread zero counting and the lane scan (fixed adds at
  1/2/3/4/8/12/16/32/48/64/128/192) and packs four counters per `uint`. The reconstruction uses
  the equivalent scalar scan. Interface matches; the instruction sequence does not.
- Validity uses `tid.x * 4 + k >= numKeys` (`cb0[1].y`), i.e. consecutive keys per thread.
- Entry-point name is not present in the RDEF; `RadixSortSort` is descriptive.
